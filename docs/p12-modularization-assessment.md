# P12 backend modularization: assessment (19 October 2026)

Facts measured from the tree, not claims of completion. `server.py` is 11,570 lines with 353 functions (61 mention scheduling terms); `app/services/schedule_service.py` is 1,532 lines (the SQL compatibility service). The Mongo plane lives in `app/domain`, `app/application` (50 modules), `app/api` and `app/persistence`.

| Row | State | What now enforces or evidences it | What is still monolithic |
|---|---|---|---|
| P12-01 boundaries | enforced | `tests/test_architecture_boundaries.py` (no driver, ObjectId, framework or SQL-service imports in domain/application); collection catalog; `docs/uctsm-boundary-ownership.md` | external owner approval of the map |
| P12-02 service split | partial | Review, approval, conflict resolution, manual rules, projections, commands, amendments, reminders, reports, cohort cutover are separate application services on repository ports; pure review/projection builders extracted from SQL services behind compatibility facades | `schedule_service.py` still mixes SQL validation, review, approval, context and persistence for the SQL plane; its callers (legacy router) are not migrated |
| P12-03 ingestion isolation | partial | Extraction runner consumes `DocumentPage`s and returns `ExtractionResult`s; provider/storage ports; portable canonical adapter; worker ownership fencing; identity gate before extraction | no production queue entry point for the new engine (extraction is intentionally unavailable); raw provider payload references and version provenance not audited against every live entry point |
| P12-04 patient boundary | enforced for the plane | `tests/test_pdf_boundary_writes.py`: the plane's HTTP adapters and worker adapter call services only (the single audited exception is the maker-checker denial record); authority is decided in one function (`authority.py`) | legacy `server.py` handlers still write `visit_instances` directly (inventory: 12 MIGRATE, 19 ADAPT routes) |
| P12-05 incremental cleanup | enforced as a ratchet | `scripts/server_ratchet.py` + `server_baseline.json` + `tests/test_pdf_server_ratchet.py`: server.py cannot grow or gain a scheduling-related function; `--update` can only lower the baseline; each new slice (legacy guard, observability install) is a thin hook | no duplicate code was deleted: removal needs consumer cutover evidence and approval (see `docs/runbooks/cohort-cutover-and-rollback.md`) |

Method for the next slice (characterize, extract, route, monitor, remove): pick one MIGRATE route from `docs/legacy-consumer-inventory.md`, write a characterization test against the current response, move its logic into an application service behind the existing route, watch `uctsm_legacy_consumer_requests_total{route}`, and delete the old body only after a named owner approves and the counter is zero for the agreed window.
